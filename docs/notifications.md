# 通知渠道

[文档中心](README.md) · [使用指南](usage.md) · [API 参考](api.md#通知渠道)

GateSync 首版支持飞书自定义机器人的卡片推送。每个渠道可分别启停、选择通知事件并配置卡片模板；多个渠道可以推送到不同群。

## 配置飞书

1. 在飞书群中添加“自定义机器人”，复制 Webhook。
2. 如果机器人开启了签名校验，同时复制签名密钥。
3. 打开 GateSync“通知渠道”，添加渠道，填写名称和上述配置。
4. 勾选通知事件，按需编辑对应模板，保存渠道。
5. 点击“测试发送”，再点击“确认发送测试”，检查群内收到的卡片。

Webhook 与签名密钥加密保存，读取接口不回显。编辑时留空保留已有值；取消“机器人已开启签名校验”并保存，会清除本地签名密钥。机器人侧的安全设置需要在飞书中同步调整。

仅支持 `https://open.feishu.cn/open-apis/bot/v2/hook/…` 形式的官方地址。请求禁止重定向，拨号时检查公开 IPv4 地址。飞书若设置了关键词或出口 IP 白名单，卡片内容和运行设备的出口也须满足要求。签名依赖设备时间，请保持系统时钟准确。

参考：[飞书自定义机器人使用指南](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot) · [使用自定义机器人发送卡片](https://open.feishu.cn/document/feishu-cards/quick-start/send-message-cards-with-custom-bot)。

## 通知事件

| 事件 | 触发方式 |
| --- | --- |
| 公网 IP 变更 | 成功检测到的 IP 与上次地址不同，且已有旧地址；手动和定时检测均适用 |
| 同步成功（实际变更） | 实际新增、删除或修改云端规则，且该目标同步及本地结果保存成功；规则无需修改时不产生事件 |
| 同步失败 | 目标规则同步或保存目标后的同步失败；不包括显式撤销规则 |

新渠道默认订阅公网 IP 变更。首次检测只建立基线，IP 无变化、检测失败或仅使用缓存时不会产生变更通知。同一次 IP 变化为每个订阅渠道生成一个任务，多个目标不会重复生成该事件。

单独检测时，IP 变更卡片表示出口地址已变化，不代表云端规则已经同步成功。需关注同步结果时，可分别订阅“同步成功（实际变更）”和“同步失败”；已有渠道不会自动增加订阅。

定时同步、手动“全部同步”按一轮收集结果，结束后向每个渠道发送一张卡片。单个目标同步及保存目标后的同步各自作为一轮。IP 变更、实际变更成功和失败按该渠道的订阅合并，不连续发送独立卡片；单独点击“重新检测”仍只发送 IP 变更。规则无需修改不产生成功事件，显式撤销不发送同步结果通知。反复手动重试失败目标会产生各轮对应的失败通知。

卡片中的成功数量是实际修改成功的目标数，失败数量是失败目标数，均只统计该渠道订阅的结果。包含成功和失败时显示“规则同步部分失败”。发送前会再次检查订阅，取消的事件会从待发送卡片中移除，所有事件均取消则丢弃任务。

## 卡片模板

单一事件和“合并同步结果”可分别编辑卡片 JSON 2.0，也可恢复默认。只有一个已订阅事件时使用对应事件模板，多个事件使用合并模板。IP 模板默认包含蓝色标题、红色删除线旧 IP、绿色新 IP 和更新时间。默认同步卡片按目标独立分块，资源信息和完成时间使用灰色；成功、新增或修改使用绿色，失败使用红色，删除规则使用红色删除线。错误只保留简短原因，接口、RequestId 等完整信息可在操作日志中查看。合并模板展示 IP 变化、成功和失败数量、各目标摘要及完成时间。

填写 `card` 对象本身，不填写外层 `msg_type`。模板中的 JSON 字符串可使用下列变量：

| 变量 | 内容 |
| --- | --- |
| `{{title}}` | 事件标题，测试卡片带有“测试”标记 |
| `{{old_ip}}`、`{{new_ip}}` | 旧 IP、新 IP |
| `{{time}}`、`{{timezone}}` | 事件时间、后台“计划任务”配置的时区 |
| `{{target_name}}` | 单一结果的目标名称，留空时回退资源名称或 ID |
| `{{resource_id}}`、`{{region}}` | 单一结果的资源 ID、地域 |
| `{{error}}` | 错误原因，最多保留前 1500 个字符 |
| `{{success_count}}`、`{{failure_count}}` | 本卡片包含的实际变更成功、失败目标数 |
| `{{summary}}` | 各目标结果及规则变更摘要；最多展示 10 个目标、约 2000 个字符，每个成功目标最多列 3 项变更，其余见操作日志 |
| `{{ip_summary}}` | IP 变化摘要；合并结果中仅在订阅并发生 IP 变更时填充 |
| `{{trigger}}` | 手动、自动或测试 |
| `{{site_url}}` | 后台配置的站点地址 |

例如：

```json
{
  "schema": "2.0",
  "header": {
    "template": "blue",
    "title": {"tag": "plain_text", "content": "{{title}}"}
  },
  "body": {
    "elements": [
      {"tag": "markdown", "content": "旧 IP：<font color='red'>~~{{old_ip}}~~</font>\n新 IP：<font color='green'>{{new_ip}}</font>\n更新时间：{{time}}（{{timezone}}）"}
    ]
  }
}
```

每个模板最多 16 KiB。GateSync 先解析 JSON，再替换字符串值，不执行模板代码；未知变量会被拒绝。事件数据放入 Markdown 时转义文字标记，避免目标名称或错误文本触发额外的 @ 或格式。`summary` 和 `ip_summary` 在 Markdown 中由后端添加固定颜色和删除线，原始事件文字仍先转义；在其他字符串字段中保持纯文本。完整请求不得超过 20 KiB。

建议把 `{"tag":"markdown","content":"{{summary}}"}` 单独作为一个元素，渲染时会展开为各目标独立的 Markdown 组件，保留组件间距。多个文字直接拼在同一个 Markdown 中可能被飞书合并换行。已保存的自定义模板会保留，使用“恢复默认”并保存即可采用新版分块布局。

“示例预览”不会发送消息，使用与测试卡片一致的示例值。界面预览展示标题和 Markdown 文字，不覆盖飞书所有组件；可查看渲染后的 JSON，完整卡片效果以飞书接收结果为准。测试发送会实际向当前配置的群发送一张卡片，不保存未提交的表单。

## 发送与重试

自动通知先写入 SQLite 队列，再由独立后台任务发送。通知失败不会回滚 IP 缓存、改变云端同步结果或阻塞其他规则操作。

每个任务最多尝试 3 次：首次失败约 30 秒后重试，再失败约 2 分钟后进行最后一次尝试。队列和已尝试次数在重启后保留；飞书返回的业务错误也会作为失败处理。测试发送只尝试一次。

发送结果在“操作日志 → 通知发送”中查看，遵循日志保留设置。停用渠道会取消待发送任务，取消订阅会移除任务中对应的事件；删除渠道会删除全部待发送任务。已开始的网络请求可能仍会完成。

群机器人接口不提供 GateSync 可用的幂等键。响应丢失或进程在发送后退出时，重试可能产生重复消息，因此不承诺严格的仅一次送达。任务使用发送时的渠道配置；调整 Webhook 或模板也会影响尚未发送的任务。

## 新增其他渠道

后端使用统一的通知事件和 `notificationSender.Send` 接口，按渠道类型选择发送器。后续新增渠道时，实现适配器、注册发送器并补充对应的配置校验和界面，不改变 IP 检测及同步触发逻辑。当前只注册飞书，不提供其他渠道的占位配置。
